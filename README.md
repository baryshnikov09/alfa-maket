# Альфа конверты — интерактивный прототип

Два пользовательских входа и общий игровой цикл: прогноз → раздача зарплаты → карточки покупок → задание → добровольный щипок → итог → награды → следующий месяц.

Статический сайт: работает локально и на GitHub Pages без серверной части и банковских сервисов. Ставка до 9%, условия досрочного снятия, награды и партнёры явно обозначены демонстрационными примерами или заглушками.

## Публикация на GitHub Pages

В репозитории настроен workflow [Test and deploy GitHub Pages](.github/workflows/pages.yml): сборка, тесты, проверка путей и публикация после push в `main`. Pull request проходит проверки без публикации.

1. Создайте пустой репозиторий на GitHub без начальных файлов. Для GitHub Free используйте публичный репозиторий.
2. Отправьте подготовленную папку на GitHub, заменив `OWNER` и `REPO`:

   ```sh
   git remote add origin https://github.com/OWNER/REPO.git
   git push -u origin main
   ```

3. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. В **Actions → Test and deploy GitHub Pages → Run workflow** запустите публикацию для `main`. Первый запуск до включения Pages может остановиться на настройке Pages; после выбора источника запустите workflow ещё раз.

Ссылка на готовый сайт появится в запуске workflow и в **Settings → Pages**. Обычный адрес: `https://OWNER.github.io/REPO/`. Главная открывает банковскую оболочку; кнопка «Игровой стол» запускает игру. Прямая ссылка на готовый стол: `https://OWNER.github.io/REPO/screens/25.html#table`.

Пути к скриптам, стилям, шрифту и каталогу относительные, поэтому переименование репозитория не требует менять код. Переходы игры используют `#table`, `#goal` и другие hash-маршруты; для них не нужна серверная переадресация. Файл `.nojekyll` позволяет также публиковать готовые файлы из корня ветки, если выбран источник **Deploy from a branch → main → /(root)**. При таком способе публикация не зависит от проверок workflow; основной настроенный способ — GitHub Actions.

Для сборки публикуемого сайта локально:

```sh
npm run build:pages
npm run check:pages
python3 -m http.server 8768 --bind 127.0.0.1 --directory dist
```

Откройте `http://127.0.0.1:8768/`. В `dist/` попадают только HTML, JavaScript, CSS, шрифт с лицензией и значок. Исходники Figma, инструменты сборки и тесты остаются в репозитории. `dist/` и `node_modules/` исключены из Git. Секреты и отдельный токен для Pages не требуются: workflow использует штатный `GITHUB_TOKEN`.

Порядок настройки соответствует [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Запуск

Установка зависимостей для работы интерфейса не нужна. Запустите сервер:

```sh
python3 -m http.server 8767 --bind 127.0.0.1
```

Откройте [главную](http://127.0.0.1:8767/index.html#bank). Кнопка «Игровой стол» открывает игру. Остальные банковские разделы — заглушки. В игре через «Об игре» доступны два сценария: существующий клиент и новый клиент. «Начать» / «Оформить карту и попробовать» запускают соответствующий сценарий заново. Для продолжения используйте «Продолжить мой разбор».

Можно открыть `index.html` напрямую, но локальный сервер обеспечивает одинаковое хранилище для всех страниц. JavaScript должен быть включён. Состояние сохраняется в текущей сессии браузера: после обновления страницы и возврата покупки, настройки, цели и переводы остаются.

## Что можно пройти

- Вход A: пробная партия из 10 операций прошлого месяца, рассчитанная экономия, свой ввод и прогноз по средним за три месяца.
- Вход B: демонстрационная цифровая карта, примеры без влияния на баланс, пустой прогноз, перенос зарплаты, пустая рука и первая настоящая карточка. Первый щипок доступен после первого итога.
- Любые суммы прогноза и щипка; цель с суммой и сроком, расчёт ежемесячного взноса, дохода и даты достижения.
- Пять базовых и пять дополнительных конвертов; добавление в одно касание, собственные конверты, переименование, удаление и новые цели.
- Раздача зарплаты и аванса, изменение сумм, включение автоматической раздачи без автоматических переводов во вклад.
- Перенос карточек мышью, пальцем, касанием или с клавиатуры. Подсветка рекомендации, прокрутка при переносе к краю, отмена мимо конверта или Esc, отмена последнего действия и разбор по подсказкам.
- История, перекладывание, отдельные карточки возврата, Вне плана, Запас, привязки категорий и правила «Всегда сюда».
- Задания с причинами, сроком, прогрессом, принятием, откладыванием и заменой. Чувствительные расходы не включаются в задания на сокращение.
- Открытие вклада с условиями и подтверждением выбранной суммы; досрочное снятие; регулярное предложение щипка с обязательным отдельным подтверждением.
- Этапы 25/50/75/100%, заглушки партнёров, достижение и создание следующей цели.
- Итог с исходным/изменённым прогнозом, фактом, Вне плана, совпадением, экономией и щипками. Новый месяц сохраняет накопления и правила.
- Награды за дни, прогноз, задания и щипки; виды и условия доступны заранее.

Над столом — «Ход месяца»: шесть шагов и следующее действие по состоянию сессии. Здесь доступны все операции, правила магазинов, регулярный щипок и награды. Под конвертами с доступным остатком есть прямое предложение щипка; условия и выбранная сумма показаны до перевода.

В блоке «Попробовать события месяца» можно показать новые покупки, зарплату, аванс и следующий день. Уведомления отражают эти события внутри прототипа; разрешения на системные push-уведомления не требуются.

В «Все операции» работают выбор месяца, фильтр конверта и поиск магазина. Покупку можно переложить, включить правило или показать частичный возврат. Покупки прошлого месяца доступны для возврата в текущем; исходный итог остаётся в архиве. «Итоги» → «Предыдущие месяцы» открывает сохранённые прогнозы и факты.

Регулярное предложение закреплено за выбранной целью и исполняется один раз. Повторное подтверждение перевода не списывает деньги снова; повторное принятие или откладывание задания сохраняет прогресс. «Открыть вклад позже, сохранить расчёт» сохраняет введённые параметры цели.

## Файлы

- `board-state.js` — общая модель данных и денежных расчётов.
- `app.js` — формы, сценарии, маршрутизация, представления и сохранение сессии.
- `board.js` — отдельный контроллер перетаскивания и выбора карточек.
- `styles.css`, `screens.css`, `game.css` — стили, адаптация, рука и состояния конвертов.
- `index.html`, `screens/01.html`–`screens/73.html` — оболочка и исходные состояния. При включённом JavaScript они используют общую модель и маршруты вида `#table`, `#forecast`, `#goal`.
- `figma-source/`, `screens.json`, `routes.json` — исходные материалы экспорта и данные для генерации экранов.
- `build_screens.py`, `build_site.py` — генераторы исходных экранов и HTML-оболочки.
- `build_pages.py` — сборка публикуемых файлов в `dist/`; `scripts/check_pages.py` — проверка ссылок под путём репозитория.
- `.github/workflows/pages.yml` — проверки и публикация в GitHub Pages.
- `tests/` — проверки расчётов, пользовательских путей и событий перетаскивания.

Для повторной сборки после замены SVG:

```sh
python3 build_screens.py
python3 build_site.py
```

Логика общей модели и перетаскивания при пересборке сохраняется.

## Проверка

```sh
npm ci --ignore-scripts
npm test
npm run build
npm run build:pages
npm run check:pages
```

Зависимость jsdom нужна только для автоматических проверок DOM. Базовые расчёты можно отдельно проверить без установки зависимостей: `node --test tests/board-state.test.js`.

Для проверок используется Node.js 24 (см. `.nvmrc`) и Python 3.13. Для обычного просмотра Node.js не нужен.

Автоматическая проверка: тесты модели, форм, маршрутов, обоих входов, перетаскивания и работы под путём GitHub Pages. Отдельная проверка сборки проходит все 74 HTML-страницы и ссылки на стили, скрипты и шрифт. В Safari проверены новый ход месяца, история и перенос карточки в Запас с сохранением баланса карты.

Открытые продуктовые вопросы реализованы как явно обозначенные допущения: допуск совпадения 5% или 100 ₽, неограниченная замена заданий, аналитика для B после 3 покупок и первого итога, сохранение исходного прогноза при правках. Реальные параметры и условия остаются для согласования.

Визуальное оформление: спокойная серая банковская оболочка, отдельный светлый игровой стол, белые конверты и карточки с красными акцентами, веер покупок и панель цели. Контроллер перетаскивания и сохранённые сценарии остаются общими.

Палитра игрового стола: Альфа-красный `#EF3124`, чёрный `#000000`, белый `#FFFFFF`, графитовый `#505759`, светло-серый `#D9D9D6`. Основной текст — 15–18 px, суммы — 26–35 px; вспомогательные подписи не мельче 12 px. Размеры сохраняются и на узких экранах.
